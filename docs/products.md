# WuwaTerm 产品入口

WuwaTerm 可以按需要选择 Telegram、Windows 或 Web。核心仓库负责共享词典、翻译与审校逻辑、HTTP API、数据构建验证以及通用部署恢复工具。各产品独立维护源码和发布；[机器可读索引](../contracts/products.json)记录了截至 2026-11-25 的源码与接口快照、各产品的发布资产校验和，以及安装器默认下载的 Web 与 Telegram 版本。要安装新版本，请再核对各仓库的发布页与说明。

## 选择使用方式

- **只用 Telegram**：使用 [Telegram 安装与运行指南](https://github.com/My-Denia/WuwaTerm-Telegram/blob/92962646e21c195f52f7eb31174b84b9b6c7f0d6/README.md)，准备 bot token、单独构建的术语数据库和指南要求的 Core wheel；不需要运行 HTTP API。当前 `0.5.0` 已正式发布，`core-lock.json` 固定的就是 Core `v0.12.0` 发布 wheel（`b243fa06…`），[制品校验说明](https://github.com/My-Denia/WuwaTerm-Telegram/blob/92962646e21c195f52f7eb31174b84b9b6c7f0d6/docs/artifact-verification.md)解释如何校验。Core `v0.10.2`–`v0.12.0` tag 的冻结快照记录的 Telegram 默认仍是 `v0.4.1`，从这些 tag 安装时传 `WUWATERM_TELEGRAM_VERSION=v0.5.0`，或改用 `main`。
- **只用 Windows 客户端**：从 [Windows v0.6.5 发布页](https://github.com/My-Denia/WuwaTerm-Windows/releases/tag/v0.6.5)下载并核对便携包；[使用与构建指南](https://github.com/My-Denia/WuwaTerm-Windows/blob/502ac8293979ab730f5d0c16bd1c59cb958ef76d/README.md)列出了操作步骤。稿件可离线编辑、保存；在线查词、翻译和审校需要运营方提供的兼容 API 地址及设备令牌。程序未签名。
- **使用 Web 和 API**：公共工作台入口及使用说明见 [Web 产品指南](https://github.com/My-Denia/WuwaTerm-Web/blob/d702328e4f2a6f5026504b2b0eaf331995f214be/docs/sites.md)。自托管时先按 [Core 自托管指南](self-hosting.md)和[数据构建指南](data-refresh.md)准备 API 与词典，再按 Web 仓库自己的说明配置 Node 运行环境、设备令牌和带认证的 HTTPS 反向代理。根路径与路径前缀需要对应构建，[Web v0.4.4 发布页](https://github.com/My-Denia/WuwaTerm-Web/releases/tag/v0.4.4)分别提供 root 与 `/private` 两套包，`v0.4.3`、`v0.4.2`、`v0.4.1`、`v0.4.0`、`v0.3.1`、`v0.3.0`、`v0.2.0`、`v0.1.1` 与 `v0.1.0` 的包仍可下载。同一工作台支持公共和自托管方式，Sites 是托管目标；此 Core 检出的安装器默认下载的就是 `v0.4.4`。
- **一条命令安装 Core（可选加 Telegram 或 Web）**：在 Core 检出目录运行 `./deploy/setup.sh` 只启动共享翻译服务；`--with-telegram` 不再安装 Core 检出里的旧 bot，它会定位独立的 Telegram 产品、按本机路径输出该产品自己的安装步骤，并在给出 `--telegram-dir` 时把那本检出的 `.env`（只含 bot 自己的设置）和 `data/terms.db` 副本准备好；旧的内联 bot 保留在 `--with-legacy-bot` 之下：`./deploy/setup.sh` 默认不启动它，Compose 文件里仍保留该服务（`deploy/product-update.sh` 按服务名解析已装服务，放在 profile 后会让更新路径看不到它，因此不改 Compose 结构）。`--with-web` 在首次安装或已有服务上增量添加 Web；`--status`/`--check` 查看组件、数据版本与健康，两者分别报告独立 Telegram 产品（`telegram`）与旧内联 bot（`legacy bot`）。安装器默认使用官方预构建镜像、缺库时构建词典、等待就绪并签发首个设备令牌，详见 [自托管指南](self-hosting.md#one-command-deploysetupsh)。`--with-web` 直接读取 WuwaTerm-Web `v0.4.4` 已发布的 `manifest-{root|prefix}.json` 与 `SHA256SUMS-{root|prefix}`，校验并解包 `archive.name` 指向的归档，运行其中的 `bundle/start.mjs`；`--web-origin` 提供反向代理对外的 HTTPS 源，就绪检查会带 `X-WuwaTerm-Edge` 请求页面与 `/api/pool`。Web 的 SQLite 准入库由 `WUWATERM_LOCAL_DB_PATH` 决定，默认 `/var/lib/wuwaterm-web/pool.sqlite3`，宿主的 `state-web/data/` 挂到该文件所在目录，不落在只读的 `/app` 包里，所以 Docker 不需要在只读挂载下创建挂载点；旧 `web.env` 写的 `/app/data/pool.sqlite3` 仍可用，安装器会先在解包目录里建好挂载点，相对路径则直接拒绝。本地包可用 `--web-package`。只有真的拿到部署指针和它指向的 manifest 才算已接管，干净安装上的 `adopt` 失败会如实报告为未接管，并在下次运行时重试。

当前 Core 源码仍保留旧 Telegram 和私有 Python Web 入口；独立产品的源码合并与替代交付分开推进，替代交付以各产品的部署记录为准。迁移状态文件时，先按各产品指南备份和核对。

安装器默认 Web 版及其他三个产品的正式版资产 SHA-256 记录在[索引](../contracts/products.json)。Web v0.4.4 的 root 归档 SHA-256 为 `606f1a7d213a2063d515590a3c5b4f3927c1641350afc19d1d335a4977a6cbfc`，`/private` 归档为 `e78ffacc05511284d296e3293ce48014f918c27aa5ed3683ae922c6e6aeb2578`。Web 发布包里 `archive.name` 指向归档，入口是 `bundle/start.mjs`，路径前缀记在 manifest 与 `bundle/BUILD-INFO.json`；`deploy/setup.sh` 按这份真实结构安装和检查，不再要求早期设想中实际并不存在的 `start`、`port`、`health_path` 字段（本地包若提供仍会采用）。

Windows 与 Web 的在线功能使用 Core `/v1` API；稿件审校需要 `review-v2`，两端稿件文件格式为 `wuwaterm-manuscript-v1`、`v2`、`v3` 和 `v4`：`v1`、`v2` 保持原义，带按段落记录的长稿件使用 `v3`，`v4` 把发现、决议与选择的条目上限提到 128 并允许「未评估」带原因，写盘时取能装下内容的最低一档，不需要 `v4` 的稿件保持低格式。`v3` 的段落术语结果只有在内容哈希、审校依据和请求输入都与一次实时 `review-v2` 依据一致时才复用，其余导入内容仍是历史，不当作新检查。`v3` 已随 Web v0.3.0 和 Windows v0.5.0 发布，`v4` 已随 Web v0.4.0 和 Windows v0.6.0 发布；`v4` 之前的客户端会拒绝 `v4` 文件。两端复核请求都声明 `X-WuwaTerm-Review-Features: dense-128,reason-v1`，不带这个头时 Core 仍返回 32 条的七键文档。API 版本相同本身不足以证明审校或私有 Web 可用：私有 Web 还要求 `GET /v1/auth/status`，其代理也严格校验响应结构。Core 同时支持 `review-v1` 和 `review-v2`，默认是前者。Telegram 直接使用固定版本的 Core 包和 schema `2` 术语数据库；它的聊天设置是 JSON，频道回复索引版本为 `1`。API 设备库和私有 Web 的准入计数库各自独立于术语数据库，后者当前为 schema `1`。具体组合和 CI 固定版本见[索引](../contracts/products.json)，不要将某一组契约测试推广到所有版本组合。

Windows 0.6.5（及历史 0.6.4–0.6.0）与 Web 0.4.4（及历史 0.4.3–0.4.0）的记录见上表及各自发布页。Windows `f60e1461` 与 Web `dfa3cf40` 的六个共享状态案例和 13 项 v1–v4 双向稿件检查通过（[Windows #34](https://github.com/My-Denia/WuwaTerm-Windows/pull/34)、[Web #48](https://github.com/My-Denia/WuwaTerm-Web/pull/48)）；MY-350 7 个重复段归因契约案例与跨端双向稿件一致检查已在 [Web #54](https://github.com/My-Denia/WuwaTerm-Web/pull/54)（`afd22cc`）、[Windows #43](https://github.com/My-Denia/WuwaTerm-Windows/pull/43)（`a45dbf2`）与 [Web #55](https://github.com/My-Denia/WuwaTerm-Web/pull/55)（`052c6be`，Windows `902 passed, 1 skipped` 与 `windows-manuscript.test.mjs` `14/14` 通过）合入，并随 Windows v0.6.5 与 Web v0.4.4 发布。发布四个正式版与部署线上服务分别记录。
