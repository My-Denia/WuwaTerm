# ADR 0016: 以双语稿件为中心的桌面工作台

- Status: Accepted（2026-11-06 owner 选择首个展示的高保真方案；实现仍须通过功能与视觉验收）
- Date: 2026-11-06
- Supersedes: [ADR 0013](0013-client-ui-visual-and-layout.md) 的布局、无图标资源及请求 ID 常驻位置；保留其来源、成本、传输和错误反馈约束
- Related: [ADR 0011](0011-pc-client-stack.md)、[ADR 0015](0015-desktop-manuscript-workflow.md)、[MY-201](https://linear.app/my-denia/issue/MY-201)

## 原有设计解决的问题

ADR 0013 将查词、可能产生模型费用的翻译和服务诊断分开，使来源与成本可辨，
同时用中文、内联错误和键盘入口改善原生控件界面。其固定导航和容器布局也限制了
首期工程改动。2026 年 8 月的截图签收针对当时交付，不能证明新增长文工作台的
构图、排版和操作体验。

11 月新增稿件编辑后，两个限高编辑框、文件按钮、报告、发现列表和替换表单依次
排列在整页滚动区。功能能够被测试，却使长文编辑退居辅助位置。Owner 因此要求：
“完成一次具有实际视觉品质的 Windows 工作台重新设计，并在真实应用中采用”。
随后选择三个实际展示概念中的第一个，采用双栏编辑、右侧上下文审校和窄活动栏。

## 决定

继续使用 Python、PySide6 Widgets 和现有协议。以本地稿件为默认落地页，一份活动
稿件的原文和译文占据主要工作面积。编辑器用可调分栏，移除 160px 高度上限；右侧
审校面板可收起。紧凑文档工具栏提供文件身份、未保存状态和明确的审校动作。

查词、翻译与稿件共享字体、间距、表面和图标系统，各自保留明确任务。翻译由显式
动作触发，预填和切页不产生请求；来源、词典未命中、取消等待和可能发生的模型费用
继续如实表达。服务配置和诊断退到设置与辅助入口，不占据本地编辑的主要空间。

本地编辑和文件操作不以服务地址或令牌为前提。在线动作仍需明确配置的安全地址及
设备凭据，缺少凭据时在传输前拒绝。无启动探测、匿名身份或默认开发服务器。
未配置服务时仍允许保存外观设置，不新增隐式断开或替换地址行为。

视觉采用深石墨分层表面、克制青绿强调、清楚的字体级差与一致的细线图标。保持
亮色、暗色和跟随系统的用户选择，不覆盖已有外观偏好。使用随包分发且保留许可的
小型 SVG 图标子集，不引入 GPL Fluent 组件、图标字体或运行时网络资源。
保留原生窗口框架和系统文件对话框。

审校面板只表达实际报告中的跨度、候选、分类、规则与 verdict。概念图中的背景说明
不作为官方资料实现；没有目标跨度时说明手动编辑路径。词对一致不代表整句或整稿
语义通过。请求 ID 可以收进诊断，成功、失败及空结果仍须能查到。

## 原有问题现在由什么解决

查词与付费翻译仍有独立入口、显式提交和来源说明。错误保持内联，凭据移除与未保存
稿件等真实决策仍可使用对话框。文件格式、原子保存、导入历史的可信度、过期响应
隔离、Unicode 与 IME 行为沿用现有领域处理，不通过重做状态模型来实现视觉改版。
旧布局测试迁移为任务与行为断言，不让旧控件数量成为新信息架构的限制。

## 验收

功能和视觉分别判断，两者都要满足。运行客户端套件、项目验证、资源打包与产物自检；
重点保留真实编辑、修订撤销、保存失败、未保存确认、历史不认证、旧响应丢弃和
IME 取消／提交与鼠标保存保护。

在实际 Qt 应用捕获稿件、查词、翻译和设置，以及空态、当前报告、过期、错误、历史与
文件冲突状态。使用与选定方案相同的视口、主题和合成稿件对照字体、构图、图标、
层次与内容。常用 1440×900、1280×800 布局应以编辑内容为主；较小工作区须可收起
辅助面板并到达必要动作。原生 Windows 另验字体、缩放、键盘、IME 和文件对话框。
Linux offscreen 截图、CI 成功和旧版本截图各自只证明其实际覆盖内容。

源码集成、原生验收、正式客户端发布和生产部署分别记录；本决定不授权部署。
