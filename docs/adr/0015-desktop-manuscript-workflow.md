# ADR 0015: 桌面稿件审校与保存

- Status: Accepted
- Date: 2026-11-04
- 关联：[ADR 0011](0011-pc-client-stack.md)（客户端与传输）、
  [ADR 0013](0013-client-ui-visual-and-layout.md)（已签收的客户端界面）

## Context

既有桌面客户端提供查词、翻译和服务状态，不能保存双语稿件或让用户继续处理一份审校结果。
用户选择「优先本地稿件工作台（推荐）」，需要从编辑、审校和单次修订一直走到本地保存及重开。

ADR 0013 保留三个独立功能区，并用内联错误取代打断操作的普通错误弹窗：查词和可能花费模型
额度的翻译有不同节奏，结果来源也要清楚，日常请求失败不应夺走焦点。当时的设计只为遗忘
令牌与关于保留模态例外。稿件引入了新情况：关闭窗口、新建或打开另一份文件会丢失尚未保存
的正文；如果仍无确认就继续，用户可能失去本地工作。

## Decision

- 保留原有三个区域和快捷键，在导航中增加独立的「稿件审校」区及 `Ctrl+4`。客户端继续使用
  受保护的设备令牌 API，领域翻译和审校判断仍由服务端负责；没有把公共 Web 的匿名身份当成
  桌面设备凭据。
- 原文、译文和方向由用户编辑，显式按「审校」才请求 `/v1/reviews`。每侧最多 2,000 个
  Unicode 字符；超过上限时不请求、不截断。报告可定位两侧的对应位置，用户可修改选中的一处
  并通过按钮或文本框快捷键撤销、重做稿件更改。撤销和重做不回退后来追加的历史报告，不更改
  当前保存路径或保存基线。正文或方向修改、服务器地址变化及请求过期会使当前报告失效。报告
  只涵盖术语约束与基础结构，不代表完整句意通过。
- 工作稿使用公共 Web 的 `wuwaterm-manuscript-v1` UTF-8 JSON 格式，单个文件上限 1 MiB；
  它与审校请求的长度上限分别计算。保存使用同目录临时文件、刷新文件内容后替换目标；写入
  失败保留已有目标及未保存的稿件。导入文件时仅提示历史报告状态，文件中的选择予以保留但
  不自动应用或认证；重新审校后才有新的当前报告。公共 Web 的完整选择确认流程尚不在桌面端。
- 若源文编辑让多条历史选择汇聚到同一位置，保存会提示冲突，让用户逐项选择移除；移除可以
  撤销或重做，未选中的历史选择及报告保留，处理后才能保存该稿件。
- 如果导入稿件带有显式段落对应，修改正文或方向会清除已过期的对应，而不自动改用推测。
  用户可主动选择「使用自动对应」，之后重新审校才按服务端的自动对应规则处理。
- 文件选择需要系统文件对话框。有未保存更改时，在关闭窗口、新建或打开另一份稿件之前询问
  保存、放弃或取消；取消或保存失败必须留下当前稿件。此新增确认只针对真实的工作丢失风险，
  普通 API 请求错误继续在区域内显示，不恢复普通错误弹窗。

## Consequences

- 稿件可以跨应用交接并在桌面重开；报告历史与当前可信状态分开，避免把导入的旧结果当作
  新检查。较长稿件仍可保存，但需要自行调整到审校长度限制后提交。
- 文本位置必须在 Unicode 字符偏移与 Qt 的 UTF-16 位置之间正确转换；显示和编辑不能悄悄
  改写文件原文。单次修订、撤销、保存失败、导入失败、请求交错及换址都必须验证。
- 增加的文件选择与未保存确认是 ADR 0013 模态规则的窄例外；原规则解决的普通失败打断问题
  仍由内联提示解决。该例外不会改变原有查词、翻译、凭据存储或传输安全约束。
- 本记录描述源码决定，不宣称已发布、部署或通过 Windows 真机验收。离屏 Qt 测试和实际
  Windows 的键盘、主题、缩放检查是不同的证据。
